  <files>src/retrieve.ts, src/index.ts, tests/retrieve.test.ts</files>
  <read_first>src/graph/query.ts (getSymbolByName, getDependents), src/graph/db.ts (initDb + the schema), src/types.ts (Symbol/File), src/health.ts (loadConfig NOT used here — retrieval does not consult config in v1)</read_first>
  <action>
Create `src/retrieve.ts` with three exports: `tokenize`, `tfidf`, `retrieve`. The retrieval corpus is: every row in the `files` table joined with its exported `symbols` (name + first line of the symbol body). For v1 we use the symbol name as the only text feature (the first-line-of-symbol-body is added in Task 2.6 alongside the minimal payload).

1. `tokenize(text: string): string[]` — lowercase the input, split on `/[^a-z0-9_]+/`, drop empty strings and tokens of length <= 1, return as a deduplicated array (preserving first-seen order). Example: `tokenize("getUserById_v2")` -> `['getuserbyid', 'v2']` (PITFALL / CONTEXT trade-off: camelCase is not split in v1, but the symbol name is still searchable as a single token; good enough for v1).

2. `tfidf(query: string[], docs: string[][]): number[]` — for each doc, compute `sum over query tokens t of (1 + log(tf_in_doc)) * (1 + log(N / (1 + df)))` where `tf_in_doc` is the count of `t` in the doc, `N = docs.length`, `df` = number of docs containing `t`. Use smoothed IDF `log(1 + N / (1 + df))` (PITFALL 5 — never `log(N / df)`). Return one score per doc, in the same order as the input. If a query token does not appear in any doc, the doc score just lacks that term; no NaN.

3. `retrieve(db, query: string, opts?: { topK?: number }): RetrieveHit[]` — the high-level function. Defaults: `topK = 10`. Steps:
    a. `tokens = tokenize(query)`. If empty, return `[]`.
    b. `seedRows = []` — for every token, call `getSymbolByName(db, tokenLower)` and union. Note: `getSymbolByName` does a case-sensitive `=` match (CONTEXT decision: case-insensitive at the query layer means the caller is responsible; we lowercase tokens and pass the lowercased symbol name). This will miss symbols whose name contains the token as a substring (e.g. token 'auth' won't match symbol 'authenticate'). To handle that, also do a `SELECT id, file_id, name, kind, start_line, end_line, exported FROM symbols WHERE LOWER(name) LIKE ?` with `'%' + token + '%'` and union with the exact-match set. Use one prepared statement per token.
    c. For graph expansion, call `getDependents(db, seedSymbolId, 2)` per seed (BFS up to depth 2 — PITFALL 4: this returns symbol IDs only; their files are NOT in the result). Collect `seedFileIds` (file_ids of seed rows) and `dependentFileIds` (file_ids of dependent rows). Union them.
    d. For each candidate file (union), build a doc = `[<file path tokens>, ...<symbol name tokens of exported symbols in this file>]` (PITFALL: no file body, ever — RTRV-03).
    e. For each candidate file, compute `graphProximity = 1 / (1 + minBfsDepthToAnySeed)` where `minBfsDepthToAnySeed` is 0 if the file is in `seedFileIds` (the file directly contains a seed symbol), 1 if the file is in the depth-1 frontier of `getDependents(seed, 1)`, 2 if in depth-2. Default to 3 (penalty) if the file is not reachable. Implement this with a single BFS over edges that records depth; or three calls (`getDependents(seed, 0/1/2)` and union by file_id). The simpler approach is to call `getDependents(seed, 1)` and `getDependents(seed, 2)` separately, then bucket by depth. Note that `getDependents(seed, 0)` returns `[]` per `query.ts` (the loop does not execute for `d=0`). So the bucket logic is: a file containing a seed -> 0; a file appearing in `getDependents(seed, 1)`-resolved file_ids -> 1; in `getDependents(seed, 2)` -> 2.
    f. `tf = tfidf(tokens, docs)`; `final = 0.6 * tf + 0.4 * graphProximity` per CONTEXT.md.
